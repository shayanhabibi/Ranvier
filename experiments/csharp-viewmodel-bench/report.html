Measurement scope

The WPF replay uses real TextBox and TextBlock controls, two-way binding and dispatcher processing. Quantity edits, refreshes, failures/retries, one-of-100-row edits and screen lifetime are measured. Screen lifetime includes controls, bindings, view models and graphs.

Several steady-state timing ranges overlap. Values are medians of batch means, not latency percentiles or confidence intervals. Allocations cover the UI thread and include the service stubs and harness. No window painting, layout, GPU presentation or real HTTP latency is measured.

The delayed-service flow requests a 10 ms timer; actual observed latency is about 28 ms due to timer resolution and scheduling. It provides no clear performance advantage for either implementation. The no-op assignment is also close to harness overhead.
